## RECOMMENDATION
Fork rclone-ui/rclone-ui (Apache-2.0, Tauri 2 + React, v3.7.1 of 2026-07-15) and keep rclone (MIT) as the transfer engine via its async rc API. It is the only living, permissively licensed project that already solves ~80% of the hard requirements: dual-pane Commander with independent per-panel navigation while async rclone jobs run (the exact CuteFTP failure mode, solved by architecture), parallel transfers via --transfers plus per-file multi-stream via --multi-thread-streams (works over SFTP concurrent reads — 'faster secure mechanism' without leaving SFTP), and a Windows x64 build already cross-compiled from Linux via cargo-xwin in its package.json. The delta work is well-scoped: an app-level transfer-queue manager with pause/resume built on rclone jobids + partial-file resume, SFTP-first site-manager UX, and reskinning. Every alternative fails a hard constraint: WinSCP needs a proprietary Windows-only compiler and is GPL; FileZilla/Cyberduck are GPL-3 with hostile toolchains; RcloneBrowser and rclone-webui-react are dead; RcloneView is proprietary; Spacedrive is FSL-licensed; the Avalonia route just lost its TreeDataGrid to a commercial license (archived 2025-10-13). Greenfield-with-libraries is the fallback only if the fork's UI proves too divergent — but it would converge on the identical Tauri+React+rclone-rcd architecture rclone-ui already ships.

## FINDINGS
All GitHub metadata gathered 2026-08-01 via gh API (stars / last push / license verified directly, not from memory).

RCLONE ECOSYSTEM (engine + GUIs)
- rclone/rclone: 58,854 stars, pushed 2026-07-31 (daily activity), MIT, Go. Cross-compiles to Windows x64 from Linux trivially (GOOS=windows). Its rc/rcd HTTP API is fully async (jobid-based), which is exactly what enables "browse while transfers run". Provides --transfers (parallel files) and --multi-thread-streams (multi-stream per file, works with SFTP concurrent reads), core/stats for per-job progress, job/stop for cancellation.
- rclone-ui/rclone-ui: 2,157 stars, Apache-2.0, very active (v3.7.1 released 2026-07-15; v3.6.0 2026-06-05). Stack: Tauri 2 + React + TypeScript + HeroUI/NextUI, Rust sidecar code. Verified from source tree: it already has a dual-pane "Commander" page (src/pages/Commander.tsx uses left/right FilePanel refs, react-resizable-panels), a navigator component suite (FileList, FilePanel, PathBreadcrumb, RemoteSidebar, PreviewDrawer, useFileNavigation), and drives rclone via the rc API with async jobids (/sync/copy, /operations/copyfile → jobid tracking, panel refresh on completion). Also has: cross-platform scheduler (schtasks.rs/launchd.rs/crontab.rs), notifications/webhooks, mount management. package.json contains `build:windows: tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc` — i.e., the project ALREADY cross-compiles Windows x64 builds from non-Windows hosts via cargo-xwin. Distributed via winget/choco/scoop/brew/flathub. Verdict: FORK — this is the 80%+ project.
- kapitainsky/RcloneBrowser: 2,940 stars, MIT, C++/Qt5. Last release 1.8.0 on 2020-02-17; last push 2024-03 (trivial). Effectively dead 6 years. Verdict: ignore (steal its transfer-queue UI ideas at most). Upstream mmozeiko/RcloneBrowser archived 2019 (Unlicense).
- rclone/rclone-webui-react (built-in web GUI): 1,561 stars, MIT, React/CoreUI. Last real commit 2021-07-30; repo push 2024-06 was housekeeping. Officially bundled but stale/abandoned; rclone forum acknowledges it. Verdict: ignore as codebase; its rc-API usage is reference material.
- RcloneView (Bdrive): proprietary freemium (EULA at rcloneview.com, FREE/PLUS tiers). Cannot fork. Verdict: competitor to study, nothing more.
- NiceGUI-based rclone GUIs: GitHub search returns nothing significant. Small GUIs (deminimis/RcloneGUI GPL-3 50★, EZRclone PyQt 40★, madroots/de_rclone MIT 33★) all toy-scale. Ignore.

CLASSIC TRANSFER CLIENTS
- WinSCP (winscp/winscp): 3,744 stars, active (pushed 2026-07-28), GPL. Critical finding from its readme.md: building requires Embarcadero C++Builder 11 Professional (proprietary, Windows-only compiler) plus VS2022 build tools, nasm, objconv. Forking is practically impossible from a Linux dev machine and legally viral (GPL). Its core embeds PuTTY + FileZilla code. Verdict: steal patterns only (background-transfer-on-separate-session model, .NET assembly automation API surface).
- FileZilla: switched GPL-2 → GPL-3 with 3.70.0 (2026-04-09); latest 3.70.6 (2026-06-05). C++/wxWidgets, SVN on filezilla-project.org, monolithic, no library separation (libfilezilla is just utilities). Verdict: ignore for code; steal transfer-queue semantics (per-item retry, speed limits, queue persistence).
- Cyberduck (iterate-ch/cyberduck): 4,661 stars, GPL-3, active (2026-07-31). Java core; Windows UI is C# via ikvm — exotic toolchain. Verdict: steal patterns (bookmark model, transfer queue with segmented downloads — Cyberduck does multi-segment downloads).
- muCommander: 1,250 stars, GPL, Java, active (2026-07-31). Dual-pane with pluggable VFS (FTP/SFTP/SMB). Verdict: steal its remote-VFS abstraction pattern.
- Krusader (KDE): GPL-2, C++/KIO, Linux-only. Ignore for a Windows target.
- termscp (veeso/termscp): 3,030 stars, MIT, Rust TUI, active (2026-07-29). Built on remotefs-rs crate family (MIT — remotefs-ssh/ftp/smb) — embeddable Rust crates if a pure-Rust engine were wanted, but remotefs-rs core only 90 stars, last push 2024-10; small bus factor.

MODERN FILE MANAGERS
- Spacedrive: 38,680 stars, pushed 2026-07-29, BUT license is FSL-1.1-ALv2 (Functional Source License — NOT open source until each release's 2-year Apache-2.0 conversion). Rust + Tauri. Verdict: steal patterns (Rust job/queue system, virtualized explorer UI); do not fork/embed current code.
- Files (files-community/Files): 44,507 stars, MIT, C#/WinUI3, very active. Windows-only and WinUI toolchain requires Windows for build/packaging — conflicts with Linux dev machine. Verdict: steal UX patterns and possibly MIT code snippets (storage abstraction, FTP support).
- xplorer (kimlimjustin): 5,639 stars, AGPL-3, Tauri/TS. AGPL is a poison pill for embedding. Ignore.
- No credible fork-ready Tauri dual-pane manager exists besides rclone-ui's Commander (searches for "file manager tauri" / "dual pane file manager" return sub-100-star or macOS/GPL projects: nimble-commander GPL-3 macOS, fman MIT 269★ Python/Qt, Waydir MIT 55★ Flutter).

GAPS IF FORKING RCLONE-UI (what must be built)
1) Real transfer queue with pause/resume: rclone rc gives async jobs + job/stop + core/stats, but no per-transfer pause. Implement an app-level queue manager that feeds rclone jobs in controlled batches; "pause" = job/stop + rely on rclone partial-file resume (multi-thread copies resume via --partial; SFTP supports ranged restarts). 2) SFTP-first site manager UX (rclone-ui is cloud-remote oriented; SFTP is just another remote — config UI already exists via remote drawers). 3) Per-file multi-stream toggle wiring (--multi-thread-streams / --multi-thread-cutoff as job params via rc _config). 4) Windows code-signing/installer polish (Tauri bundler handles NSIS/MSI).

The user's rclone instinct is validated: rclone is the only actively maintained MIT-licensed engine that simultaneously delivers parallel files + multi-stream per file + async job API + SFTP/FTPS/S3 + Linux→Windows cross-compilation, and rclone-ui is the only living, permissively-licensed GUI already built on it with a dual-pane commander.
